# Azure AZ-104
# Compute
## VM
### Availability Set
- Group of VMs perf. the same functionalities. 
- Ensure not all VMs upgrading at the same time.
- Run across multi phys. servers, racks, stoage, network switches.
- VM can only be added when created.

#### Update Domain
- Group of nodes that are upgraded together during service upgrade (roll out)
- Spec. 1~20 update domains when creating Availability Set, default: 5.
- Immutable

### Fault Domain
Group of nodes that share a common set of HW, i.e. share a single point of failure.
- 2 Fault Domains work together against HW failures.

![alt text](./asset/update-fault-domains.png)

### Scale Set
- A set of identical VMs
- Autoscaling

# Network

## Subnet
- Virtual network segmented into 1+ subnets
- Reserved: `192.168.1.0/24`
    - 192.168.1.0: identify virtual network address.
    - 192.168.1.1: default GW.
    - 192.168.1.2 & 192.168.1.3: Azure maps these Azure DNS IP to the virtual network space.
    - 192.168.1.255: broadcast

## Network Security Group (NSG)
- list of sec rules, allow/deny in/out-bound traffic
- asso. to subnet or network intf
- 1 subnet, 1 NSG

## VNet Peering
### Types 
- Global: conn. 2 VNets in diff regions
- Regional conn. 2 VNets in the same region

### VPN GW
- 1 VNet, 1 VPN GW

GW transit 
- support regional & global peering
- VNet comm. to resources outside peering via Hub VNet w/ Network Virtual Appliance (NVA) or VPN GW
- Decide NSG rules on/off b/w VNets

# Storage
## Replication Strategies
- LRS (Local): 3 replicas
- ZRS (Zone): across 3 zones in 1 region
- GRS (Geo): 6 replicas, 2 regions
- RA-GRS: GRS + Read-acc to secondary
- GZRS: 6 replicas, each AZ in primary region contains 1 replicas, secondary region contains 3 replicas
## Blob Storage
- Storage account > Container > Blob

### Application
- Serve image, doc to browser
- Distributed acc.
- Streaming audio/video
- Archive & Recovery

### Tiers
- Hot: acc./mod. often
- Cool: acc. freq: 30 days
- Cold: acc. freq: 90 days
- Archive: acc freq: 180 days, retrieval lantency takes hours.

### Lifecycle Mgmt
if-then stmt: move to cooler tier.

### Blob Types
- Block: blocks of data are assembled to make a blob, default.
- Append: block w/ append op optm., e.g. logging.
- Page: frequent R/W op. Azure VM uses page blobs for operating sys disk and data disk.

### Cost $
- Vol of data stored per month
- Quantity and types of op performed
- Data redundancy

Data acc, Transaction: tier- -> cost+ 

### Shared Access Signature (SAS)
- URI to grant restricted acc to Azure storage
- Set expiration 
- Use HTTPS

### Types
- User delegation: secured w/ Entra ID
- Service: acc to spec resources in a storage account
- Account: Service + other resources and abilities, e.g. create FS. 

### SAS params
- `sv=2015-04-05`: storage ver
- `ss=bf`: service, in casu Blob (b) & Azure Files (f)
- `st=2015-04-29T22%3A18%3A26Z`: start time
- `se=2015-04-30T02%3A23%3A26Z`: expiry time
- `sr=b`: spec which resource, in casu resource in Blob storage.
- `sp=rw`: perm, rwcdl: read, write, create, delete, list.
- `sip=168.1.5.60-168.1.5.70`: IP range
- `spr=https`: protocol
- `sig=F%6GRVAZ5Cdj2Pw4tgU7Il STkWgn7bUkkAg8P6HESXwmf%4B` HMAC signature, using SHA256 algo, Base64 encoding.
